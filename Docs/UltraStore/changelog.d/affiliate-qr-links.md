- **Every affiliate link has its QR code, and a page that makes both** (`Server/UltraStorePortal` 0.12.0, its README's *Affiliates*). An affiliate had links as text and nothing to print or to show in a video.
  - **The code is a picture beside the link**: `/r/<handle>/qr.svg` and `qr.png`, the same under a product's link and a recruiting link. `?s=<campaign>` is carried into the link the code holds, `size` is a PNG's width, `level` the error correction (Q unless said), `download=1` saves it. Asking for the picture counts no click. One address for a web page, a poster and - later - the native store.
  - **The portal draws it itself** (`ultrastore_portal/qr.py`): a port of the generator the framework bundles for its QR plugin, byte mode, versions 1 to 40, all four levels, the mask by the standard's penalty rules; the PNG through Pillow. No new dependency. Compared module for module with a second generator for every mask and read back by a decoder when it was written.
  - **The link maker**, `/affiliate/links/`: where the link leads (the shop, a product, becoming an affiliate) and the campaign give the link with a *Copy* button, what it earns, and the code to save as SVG or as PNG at 600 or 1200 px. The affiliate's page and the product list lead to it.
  - A campaign's name in a link is letters, digits, dots, dashes and underscores, 32 at most; anything else becomes a dash.

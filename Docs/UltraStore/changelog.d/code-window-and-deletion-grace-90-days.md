- **A code stays in force for 90 days, where it was 30** (`StoreSettings::kCodeDays`). The owner decided one window for a link and a code in the affiliate programme (`Docs/Research/UltraAffiliatesDesignProposal.md`), and the store's was the only one built. The status line and the hint under the code field are written from the constant and follow it; the command line's help said "(30 days)" in so many words and says 90.
- **A deleted account is kept for 90 days, where it was 30.** The account page promised "30 days" in two texts while the number lived in the account service's settings; a service set to anything else made the texts untrue. The service's default is 90 now (`Server/UltraStoreAccount` 0.3.1, `ULTRASTORE_ACCOUNT_DELETION_GRACE_DAYS`), and the two texts take the number from one constant, `kDeletionGraceDays` (`Account.h`). A deployment that sets the variable keeps its own number: set it to 90 with the store's.
- **The README's *Affiliates and codes* says where it stands.** It described the two-tier scheme of the admin backend as the decided one. A note at its head now names UltraAffiliates as the programme going forward, and what of the section carries over (the code kept by the store, the links, the QR codes) and what does not (the two tiers, a merchant's own ledger). `Docs/UltraStoreAdmin/README.md` carries the same note.

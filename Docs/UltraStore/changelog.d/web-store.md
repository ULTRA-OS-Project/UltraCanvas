- **The web store** (`Apps/UltraStore/web`, `Docs/UltraStore/WebstoreBrief.md`): the shop's Discover, categories and app pages as an UltraCanvas application a browser runs - a side module on the UltraCanvas runtime, from the UltraCanvas extension when it is installed and from the site's `runtime/<hash>/` otherwise - served from the catalog base by the admin backend's publish. The catalog comes from the site's own origin and is verified in the browser (WebCrypto's Ed25519) against the keys built in and the ones an accepted catalog announced, with the sequence check; a catalog that does not verify is not shown. *Install*, *Try* and *Buy* open the native store's `ultrastore://app/<id>` link; the page offers the store's download where the link finds none. Every page has an address (`?page=app/<id>`, the published `app/<id>/`), with an HTML shadow for search engines and the moment before the module paints. Builds natively as `ultrastore-web <publish folder>` with the demos.
- **The catalog's picture variants**: `icon_variants` and `screenshot_variants`, entries `{format, width, url}`, read leniently and written when present - the pictures at the web store's sizes and browser formats, which it picks by the format the browser decodes and the device pixel ratio, never resizing in the browser. A store that does not know the keys is unaffected.
- The catalog's writer keeps a price or an update date set on an entry before its model or period is: the admin's `app set` fields no longer vanish between two commands.
